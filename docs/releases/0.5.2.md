# Teams Connector 0.5.2

Windows start-at-sign-in setup now uses an owner-only logon trigger, so an ordinary unelevated account can enable it. This adopts the shared native platform correction while preserving existing recognized startup entries, saved configuration and conversation evidence.

The installation remains paused until its Teams and ACP setup is complete. Tenant authorization, bot registration and public callback reachability remain independent requirements. Native downloads retain private Node and production dependencies; no developer tools or WSL are required. Packages remain unsigned previews.

Native startup commands also keep OS success messages out of their JSON response. This prevents a successful registration from being reported as an invalid helper response. Captured older empty logon triggers remain recognized without rewriting saved tasks.
