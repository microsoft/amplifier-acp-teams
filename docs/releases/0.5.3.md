# Teams Connector 0.5.3

Authorized clients can inspect an exact original Teams submission, including retained delivery evidence, session transitions and last observed work references from compatible Agent Instances. Lookup uses existing records and never resends an input. The optional context provider binds source receipts to configured tenant, conversation and sender scope; enabling it requires explicit installation configuration. It does not establish live platform membership or grant new tenant access. Plain ACP remains supported, with unsupported and unknown outcomes reported explicitly.

An advertised session-load failure now preserves the original saved binding and reports the failure before sending a prompt or creating a replacement. A fresh later input can recover that same session. When an endpoint does not support loading, the existing replacement path records predecessor and current session IDs and identifies the bounded history supplied; replacement does not claim recovery of the original session or uncertain effects. Interrupted dispatches remain uncertain and are not replayed.

The patch preserves dependency selections, existing configuration, work and delivery records. Normal native updates retain the installation's Teams authorization, agent settings, conversations and startup preference. Tenant setup and provider registration remain separate; no new connection is activated by this release. Downloads remain unsigned previews. See [session handling](../session-handling.md), [management API](../api.md) and [native updates](../native-installation.md#update-or-recover-this-connector).
